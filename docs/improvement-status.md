## 성능 측정

Windows Edge headless, 1440×900, 같은 PC에서 기존 v1.0과 수정본을 순차 비교했습니다. 각 프로젝트는 텍스트 88개·이미지 요소 8개·기본 요소 4개로 총 100개, 원본 자산은 1600×2400 이미지 2개입니다. 일정 20회 변경을 세 번 측정했습니다.

| 항목 | 기존본 | 수정본 |
| --- | --- | --- |
| 메인 스레드 처리 시간 3회 | 1805 / 1725 / 1811 ms | 247 / 193 / 177 ms |
| 중앙값 | 1805 ms | 193 ms |
| 중앙값 감소 | 기준 | 약 89% |
| 미리보기 이미지 픽셀 합 | 7,680,000 | 786,432 |
| 단순 RGBA 픽셀 버퍼 추정 | 약 29.3 MiB | 약 3.0 MiB |
| 이 연속 편집 사례의 직렬화 Undo 기록 | 27,248 bytes | 116 bytes |

메인 스레드 시간은 Chrome DevTools Protocol의 TaskDuration 차이입니다. 픽셀 버퍼는 픽셀 수×4 bytes 추정이며 브라우저 전체 메모리 측정은 아닙니다. 이 결과는 해당 테스트 조건의 비교값이며 모든 PC·프로젝트의 속도를 보장하지 않습니다.

## 유지한 제약과 후속 작업

- 현재 저장은 로컬 IndexedDB입니다. Cloudflare 배포 가이드는 접속 주소를 만드는 정적 배포이며, 온라인 프로젝트 저장·기기 간 자동 동기화는 아직 포함하지 않습니다.
- 시스템 폰트를 사용하므로 Windows 외 OS의 줄바꿈은 달라질 수 있습니다. 폰트 파일 업로드·번들은 포함하지 않습니다.
- 한 화면에 최대 분량의 글을 모두 넣는 데는 한계가 있습니다. 자동으로 읽을 수 없는 크기로 줄이지 않고 수정 또는 명시적 요약을 선택합니다.
- Undo는 세션 내 70단계, 복구 기록은 프로젝트당 최대 10개/30초 간격입니다.
- 모바일 전용 화면, 여러 사람 실시간 공동 편집, 독립 데스크톱 앱은 이번 범위에 없습니다.
